The NeuroVox v2.0 companion application is the complete output interface for the NeuroVox wearable EMG device. It receives classified muscle gesture data from the hardware over Bluetooth Low Energy, passes gesture intent to a Claude Opus 4.6 API pipeline, and generates contextually complete conversational responses on behalf of the user — displaying them as readable text, speaking them aloud through the phone speaker, and logging them for caregiver review. The app is the voice of the person wearing the device.
This repository contains the full source code for the NeuroVox v2.0 mobile application built in React Native for Android and iOS.

What the App Does

Most assistive communication apps function as phrase boards — the user navigates menus to find a pre-recorded phrase and plays it. This works for highly predictable interactions but fails the moment the conversation goes off-script. NeuroVox v2.0 takes a fundamentally different approach. The hardware sends a gesture label — a short semantic tag like "HELP," "DISCOMFORT," "YES," or "WATER" — and the app sends that label to Claude Opus 4.6 with full conversational context including the patient's profile, the conversation history so far, the time of day, and any caregiver notes. Claude generates a complete, natural-language response that a person would actually say in that situation. The output is not "HELP." The output is "I need help. Could you please call the nurse? I am feeling pain in my left arm." That difference is the entire point of the project.
The app has four screens accessible from a persistent bottom tab bar.

Screen One — Live Speech Output

The Live screen is the primary interface for active communication. When a gesture is received over BLE, the screen updates in under 800ms with the Claude-generated response displayed in large, high-contrast bold text on a white card occupying the majority of the screen. The text size is configurable between 18pt and 36pt to accommodate caregivers reading from a distance. Below the response card, a Speak Aloud button triggers the phone's native text-to-speech engine to read the response aloud at a configurable volume and speech rate. A Save to History button logs the response with a timestamp to the local session history. At the bottom of the card in small muted italic text, a label reads "Generated by Claude Opus 4.6" — this attribution is intentional and permanent, because the people using this app and caring for the people using this app deserve to know what is generating the words they are reading and hearing.
The BLE connection state is shown in the header as a pulsing green dot when connected and a static red dot when disconnected. If the BLE connection drops mid-session, the app queues gesture events locally and syncs when reconnected, ensuring no communication attempt is lost.

Screen Two — Health Insights

The Health screen displays real-time and historical EMG signal data received from the hardware. A live waveform chart at the top of the screen plots the Channel 1 flexor signal amplitude in millivolts against time in seconds, updating at the BLE notify rate of approximately 50Hz. The chart uses an orange trace on a light grey background with clearly labelled axes. The current amplitude reading is displayed in bold on the top right corner of the chart card. Users can swipe left on the chart to switch between Channel 1 through Channel 4 waveforms.
Below the waveform chart, a circular gauge displays the current gesture recognition accuracy percentage computed over the last 100 classified gestures, comparing confirmed gestures against the expected calibration baseline. A green upward arrow or red downward arrow beside the percentage indicates the trend since the previous session.
A bar chart at the bottom of the screen shows gesture frequency counts for each gesture type over the past hour, giving caregivers visibility into how actively the patient is communicating and which gesture patterns they are using most frequently.
At the very bottom of the Health screen, a Claude Opus 4.6 artifact panel displays an AI-generated insight about the session's EMG data. Examples include fatigue detection based on signal amplitude degradation over time, electrode contact quality warnings based on noise floor increases, and suggestions to run recalibration when gesture accuracy drops below 80 percent. This panel updates once every fifteen minutes or on demand via a refresh button.

Screen Three — Device Status

The Device screen gives the user and caregiver a complete view of the hardware's current state. A large circular battery ring at the top of the screen displays the current battery percentage in bold white text on a deep navy background. The ring arc fills proportionally in electric blue. Below the battery indicator, three status rows display Bluetooth connection state and device name, ESP32-S3 firmware version with an up-to-date or update-available label, and current device temperature in degrees Celsius with a colour-coded dot — green for normal, orange for warm, red for thermal warning.
Four small status tiles below the rows show Signal Quality percentage in green or red, Haptic Motor state on or off, Active Channel count showing how many of the four EMG channels are currently producing valid signals above the noise floor, and IMU state active or inactive. A full-width Run Calibration button at the bottom opens the calibration flow, which walks the user through five guided muscle contractions per channel to set personalised threshold values that are written back to the ESP32-S3 NVS flash over BLE.

Screen Four — Claude Conversation

The Claude Conversation screen shows the full session conversation as a scrollable chat thread, making the interaction readable as a complete dialogue rather than isolated individual outputs. Gesture detection events appear as small italic grey labels in the thread — "Detected gesture: Extended Hold — Channel 2" — followed immediately below by the Claude-generated response in a white speech bubble with a warm gold left border. This visual distinction between raw hardware events and AI-generated language is deliberate. It makes the pipeline transparent and auditable.
The conversation history is maintained in the app's local state for the duration of the session and passed as context to every Claude API call, allowing Claude to generate responses that are coherent across the entire conversation rather than treating each gesture as an isolated input. A caregiver can scroll up to review the full exchange, export the conversation as a text file, or clear the history to start a new session.
The input bar at the bottom of the screen shows "Gesture detected here..." as placeholder text and updates in real time when a gesture arrives, giving the caregiver visual confirmation that the hardware is actively sending data even before Claude's response appears.

Claude Opus 4.6 Integration

Every gesture classified by the hardware generates an API call to Claude Opus 4.6 using Anthropic's messages endpoint. The system prompt passed to Claude on every call contains the patient's configured name, their primary language, a brief caregiver-authored description of the patient's communication context and medical situation, the full conversation history formatted as a prior turns array, and a strict instruction to generate a single natural-language response in the first person as if the patient is speaking, without any preamble, explanation, or hedging.
The gesture label is passed as the user message. Claude's response is the patient's voice. The API call is made from a lightweight Node.js backend proxy that handles API key security so the key is never embedded in the mobile app binary. The proxy adds no processing logic — it forwards the request to Anthropic's API and streams the response back to the app, which renders the text progressively as it arrives rather than waiting for the full response before displaying anything.
Average end-to-end latency from gesture detection on the hardware to full text display on the app screen is approximately 1.2 to 2.0 seconds on a standard 4G connection, which is fast enough for natural turn-taking in conversation.
